# frontend-craft：高级前端工艺

界面质量的差距不在技术在审美纪律。本技能给你三样东西：弹药地图（去哪抄高级组件）、设计纪律（反 AI 味）、落地工作流（怎么抄得对）。

## 二、反 AI 味设计纪律（每条可判定）

AI 生成的界面有股一眼假的味，根因是这些坏默认：

1. **禁止紫色渐变 + 圆角卡片 + 阴影三件套**——这是 AI 味第一特征。配色先做减法：一个背景色 + 一个前景色 + 最多一个强调色，强调色使用面积 <5%
2. **间距必须成体系**：用 4 的倍数阶梯（4/8/12/16/24/32/48），禁止 13px/17px 这类随机值；元素间距看节奏不是看均分——相关元素靠近、无关元素疏远（邻近性原则）
3. **字号层级不超过 4 级**：正文/次要/标题/展示，每级对比要明显（1.25 倍以上）；禁止满眼同号字靠颜色区分
4. **对齐是免费的精致**：同一视觉块的左边缘必须对齐；文字居中是懒惰的默认，信息类内容优先左对齐
5. **边框比阴影高级**：分隔优先用 1px 低透明度边框，阴影只给浮层（popover/tooltip）；毛玻璃/重阴影/大圆角一起出现 = 用力过猛
6. **动效必须有信息含义**：状态变化/空间关系/注意力引导才配动效；装饰性动效（无意义漂浮/闪烁）一律不加。动效时长 150-300ms，超过 400ms 的入场动画是负担
7. **空/加载/错误三态不齐 = 半成品**：任何数据驱动的界面，动手时就把三态画出来
8. **图标风格统一**：线性/填充/双色只选一种；emoji 当功能图标是玩具感来源（品牌吉祥物场景除外）
9. **暗色主题不是反色**：暗色的层次靠「海拔」——越高的层越亮（不是越深），文字透明度阶梯（100/70/50%）而非灰色阶梯
10. **信息密度尊重场景**：监控台/看板要密度优先（表格/紧凑行）；营销页要留白优先。搞反了两头都难看

## 三、落地工作流（抄组件的正确姿势）

1. **先定参照再动手**：从灵感站找 1-2 个接近目标的参照，截图/链接写进工作笔记；凭空设计的结局都是平庸
2. **抄结构不抄皮肤**：组件库抄的是 DOM 结构 + 动效逻辑，配色/字体/圆角必须换成项目自己的设计 token——原样照搬等于把别人的品牌贴进来
3. **网络受限时三级自救**：直连被重置先试 clash 7897 代理；不通则自起代理（读 C:\development\proxy\nodes.md 手册，sing-box 起 127.0.0.1:17897）
4. **抄完必验收**：build 通过只是底线；自己过一遍设计纪律十条，违反即返工
5. **一致性大于单点惊艳**：一个平庸但全站一致的界面，胜过九个惊艳组件拼成的拼布被

## 四、项目集成纪律（通用）

- 组件抄进来后必须接入**项目自己的**设计 token 体系（颜色/圆角/间距变量化），硬编码 hex 是评审红灯
- 优先使用项目已有的组件库与样式约定，禁止为抄一个组件引入新的重量级依赖
- 动画优先 CSS transform/opacity（合成层），禁止 layout 属性动画
- 改完必跑项目自己的 lint/typecheck/build 门禁，有视觉验收手段（截图对比）就用
